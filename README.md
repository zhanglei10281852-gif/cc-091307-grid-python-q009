# 社区公共设施报修统筹

面向网格中心的设施报修统筹服务：周末集中受理路灯、健身器材、楼道扶手等
公共设施报修，按风险等级与区域自动匹配维修班组，生成可追踪的处理链，
避免同一设施被重复派工，紧急故障有明确的优先级依据。

运行环境：Python 3.11（仅标准库）。代码位于 `src` 目录。

## 功能

- **受理与派工**：接收设施位置（区域+地址）、类别、风险等级、照片摘要、
  报修人联系方式；按"类别+区域"匹配班组、按负荷均衡派工，优先级依据
  （风险权重、匹配过程、班组负荷）随派工事件留痕。
- **处理链**：待派工 → 已派工 → 整改中 → 待验收 → 已完成；
  支持补充、合并、转交、暂停、验收，全程事件留痕可追踪。
- **合并可回溯**：同一设施重复报修自动合并（也可手动合并），来源单保留
  并指向主单，来源工单关闭，双方事件均可查询。
- **验收闭环**：验收不通过只能回到整改阶段，整改后重新提交验收；
  每轮验收意见单独留痕。
- **幂等事件**：班组移动端事件携带序号，重复发送幂等返回已记录结果，
  过期（序号冲突）与跳号更新被拒绝；服务端操作同样占用序号，离线缓存
  的事件在状态变化后会被正确拒绝。
- **权限脱敏**：报修人联系方式按岗位分级可见（完整 / 脱敏 / 隐藏）。
- **管理端总览**：班组负荷、超时工单及原因（按风险等级处置时限判定）、
  每项验收意见。
- **持久化**：状态与全部事件存于 SQLite（单文件），进程重启后派工状态
  与历史事件完整保留。

## 运行演示

```bash
python -m src.demo [db_path]
```

演示周末受理、自动合并、离线重发/过期拒绝、暂停/转交/补充、验收返工、
管理端总览与模拟重启的完整流程。

## 运行测试

```bash
python -m venv .venv && .venv/bin/pip install pytest
.venv/bin/python -m pytest tests/ -q
```

## 代码结构

- `src/models.py` — 领域模型：报修单、工单、班组、事件、验收记录，风险等级与时限
- `src/storage.py` — SQLite 持久化：状态表 + 事件日志（事务内一并写入）
- `src/service.py` — 核心服务：受理、派工、状态机、幂等事件、合并、验收
- `src/views.py` — 视图层：按角色脱敏、管理端总览
- `src/demo.py` — 端到端场景演示
- `tests/` — pytest 测试

## 关键约定

- 工单事件序号单调递增，班组客户端通过 `next_crew_seq(order_id)` 获取
  下一序号；`seq <= last_seq` 且内容一致视为重复（幂等返回），内容不一致
  视为过期（拒绝），`seq > last_seq + 1` 视为跳号（拒绝，需先同步）。
- 联系方式可见级别由 `CONTACT_PERMISSIONS` 配置：管理员/调度员完整可见，
  管理端/班组脱敏，访客隐藏。
